# 놀이 기록으로 배움읽기·배움지원 및 계획 생성

## 결과

교사가 하루의 [놀이 기록](../../../GLOSSARY.md)을 입력하면, 서비스가 기록을 읽고 알맞은 누리과정 영역을 골라 [배움읽기](../../../GLOSSARY.md)와 [배움지원 및 계획](../../../GLOSSARY.md) 초안을 보여 줍니다. 교사는 글을 읽고 고친 뒤, 복사해서 한글 일지 칸에 붙입니다. 이 작업 단위는 하루 한 건의 흐름을 처음부터 끝까지 동작하게 만드는 것입니다.

## 범위

- 한 화면에서 놀이 기록 하나를 입력하고 결과를 받습니다.
- 결과는 배움읽기와 배움지원 및 계획, 두 덩어리로 나뉘어 보입니다.
- 각 덩어리는 따로 복사할 수 있고, 교사가 화면에서 직접 고칠 수 있습니다.
- 글 생성은 Google Gemini API 무료 구간(Flash 계열)을 서버에서 호출합니다. 근거와 경계는 [ai-generation](../../decisions/ai-generation.md)을 따릅니다.
- 화면 구성은 [ui-composition](../../decisions/ui-composition.md)을 따릅니다.

## 수용 기준

1. 놀이 기록을 입력하고 생성 버튼을 누르면, 배움읽기와 배움지원 및 계획이 각각 표시됩니다.
2. 생성 중에는 진행 중임이 보이고, 같은 입력으로 버튼을 연달아 눌러도 요청이 중복되지 않습니다.
3. 배움읽기는 3~5줄, 배움지원 및 계획도 3~5줄의 개조식 문장(예: "~함", "~알아봄")입니다. 한국어로 쓰입니다.
4. 배움지원 및 계획의 마지막 줄은 다음 날 이어갈 계획입니다.
5. 생성된 글은 입력한 놀이 기록에 나온 내용에 근거합니다. 기록에 없는 아이의 말이나 행동을 지어내지 않습니다. 따옴표로 인용한 말이 놀이 기록에 없으면 그 줄은 결과에서 빠집니다.
6. 서비스는 기록 내용에 맞는 누리과정 5개 영역(신체운동·건강, 의사소통, 사회관계, 예술경험, 자연탐구)을 스스로 고르고, 그 영역에 맞는 관점으로 글을 씁니다. 교사가 영역을 고르는 입력은 없습니다.
6-1. 결과에는 글을 쓸 때 참고한 누리과정의 "영역 > 내용범주"가 1~3개 따로 표시됩니다(예: "자연탐구 > 탐구과정 즐기기"). 표시되는 항목은 아래 "누리과정 참고 목록"에 있는 것만이며, 목록에 없는 항목은 표시되지 않습니다.
6-2. 참고 항목은 복사되는 글(배움읽기, 배움지원 및 계획)에 섞이지 않습니다. 글 안에는 영역 이름을 쓰지 않습니다.
7. 각 덩어리의 복사 버튼을 누르면 해당 글만 클립보드에 복사되고, 복사됐음이 화면에 보입니다.
8. 교사가 결과 글을 화면에서 직접 수정할 수 있고, 복사는 수정된 글을 기준으로 합니다.
9. 입력이 비어 있으면 생성하지 않고 입력이 필요하다고 알려 줍니다.
10. 생성에 실패하면(무료 한도 초과, 네트워크 오류, 모델 오류) 이유를 알려 주고, 입력은 지워지지 않아 다시 시도할 수 있습니다. 한도 초과는 "잠시 뒤 다시 시도"로 구분해서 알려 줍니다.
11. API 키는 브라우저로 노출되지 않습니다.
12. 좁은 화면(휴대폰 폭)에서도 입력, 결과, 복사 버튼이 모두 쓸 수 있습니다.

## 확정한 제약과 이유

- 입력은 놀이 기록 하나입니다. 연령, 주제 같은 별도 입력은 받지 않습니다(`PRODUCT.md` 경계).
- 놀이 기록은 교사가 직접 씁니다. 서비스가 기록 자체를 만들어 주지 않습니다(`PRODUCT.md` 경계).
- 배움읽기와 배움지원 및 계획은 놀이에만 씁니다. 일상 기록은 입력도 출력도 없습니다.
- 생성 글은 초안이며 교사가 고치는 것을 전제로 합니다.
- 놀이 기록에 아이 이름이 들어가도 됩니다. 사용자의 판단이며, 무료 구간에서는 입력이 Google의 제품 개선에 쓰일 수 있다는 위험을 알고 선택했습니다.

## 가정 (바꾸고 싶으면 알려 주세요)

- 로그인과 저장이 없습니다. 페이지를 닫으면 입력과 결과는 사라집니다. 비용이 작고 나중에 추가하기 쉬워서 정한 기본값입니다.
- 화면은 한 페이지이고, 입력칸 하나와 생성 버튼, 결과 두 덩어리로 구성합니다.
- 참고한 누리과정은 영역과 내용범주 수준까지 보여 줍니다. 원문의 세부 내용(59개 문장)은 구하지 못해 보여 주지 않습니다. 바꿀 수 있는 가정입니다.
- 누리과정 참고 목록(15개 내용범주)은 2019 개정 누리과정의 영역별 목표와 범주를 다룬 공개 자료에서 확인한 값입니다. 교육부 고시문 원문(hwp)과 대조하지는 못했습니다.
  - 신체운동·건강: 신체활동 즐기기, 건강하게 생활하기, 안전하게 생활하기
  - 의사소통: 듣기와 말하기, 읽기와 쓰기에 관심 가지기, 책과 이야기 즐기기
  - 사회관계: 나를 알고 존중하기, 더불어 생활하기, 사회에 관심 가지기
  - 예술경험: 아름다움 찾아보기, 창의적으로 표현하기, 예술감상하기
  - 자연탐구: 탐구과정 즐기기, 생활 속에서 탐구하기, 자연과 더불어 살기
- 배포 대상은 Vercel일 가능성이 있다는 것이 사용자의 말이며, 저장소에서는 확인되지 않았습니다. 어디에 배포하든 API 키는 서버 환경 변수로만 둡니다.
- 글의 문체와 분량은 사용자가 준 예시(개조식)를 기준으로 하되, 분량은 사용자 요청으로 항목당 3~5줄로 늘렸습니다.

## 범위 밖

- 일상 기록, 사진, 일지 전체 작성, 한글 파일 내보내기: `PRODUCT.md`에서 다루지 않기로 한 영역입니다.
- 로그인, 사용자별 저장, 주간 단위 모아 보기: 이번 작업 단위에서 필요하지 않습니다.
- 아이 이름 자동 마스킹: 이름 입력을 허용하기로 했으므로 하지 않습니다.
- 사용량 제한, 남용 방지: 스펙이 요구하지 않았습니다.

## 미정 사항

- **영역별 세부 내용(59개 문장)**: 교육부 고시문 원문으로 확인해 참고 표시와 글 생성의 근거에 반영해야 합니다. 그전까지는 영역과 내용범주까지만 표시하며, 이 동작은 임시입니다.
- **성공 신호**: `PRODUCT.md`에서도 미정입니다.

## 남은 위험

- 무료 구간의 한도와 모델 목록은 자주 바뀝니다. 한도를 넘으면 그날은 생성이 실패합니다.
- 아이 이름이 담긴 기록이 외부 서비스로 전달됩니다. 무료 구간에서는 제품 개선에 쓰일 수 있습니다.
- 참고 목록을 원문과 대조하지 못해, 범주 이름이 원문과 다를 수 있습니다. 모델이 고른 참고 항목이 글의 실제 근거와 어긋날 수도 있어, 교사가 읽고 판단해야 합니다.
- 모델이 기록에 없는 내용을 덧붙일 수 있습니다. 교사가 읽고 고치는 흐름이 유일한 안전장치입니다.
